Raven Research Benchmark v1

A rerunnable set of 100 questions for comparing Raven with general-purpose and specialist research agents on the questions crypto, perp and stock-perp traders actually ask. Each question carries a checklist of verifiable facts with a reference source and tolerance, must-not items and a 0/1/2 rubric written for that question. Every agent gets each question at the same moment and is graded against a reference snapshot taken at send time.

How it's built. 40 questions come from real Raven usage logs, cleaned up and turned into templates with slots like {TICKER} and {WALLET} plus default values, so they stay reusable over time. The other 60 were written to fill gaps evenly across 10 topics that match the Eval Desk and Raven compare categories, with a mix of difficulty and type and some deliberate hard cases: missing data, wrong premises, exact timestamps, fresh news and multi-turn follow-ups.

Usage stats and the log-derived questions come from Raven's real logs (172 exchanges, 17 threads, 24 Sep – 13 Oct 2026). Questions were cleaned and generalized, and this page includes no raw user messages.

How grading works

Fill slots
Put concrete values in the template slots and log them. Swap any default that has gone stale.
Send at once
Every agent gets the question in the same second. Record the send time, latency, errors and tool calls. 240 s deadline.
Snapshot
Within 60 s, pull reference data: Hyperliquid API, Coinglass, SEC EDGAR, official announcements, onchain explorers, official calendars.
Grade blind
Score each checklist fact pass/fail against its tolerance, then apply the question's 0/1/2 rubric.
Spot-check
An LLM judge can grade first. Humans re-grade 20% plus every 0 and every hard case. Target: 85% or better agreement.

Score

2All checklist facts within tolerance, no must-not violation, sources and timestamps present, gaps admitted, false premises corrected.
1On topic and nothing made up, but a fact is missing, outside tolerance, stale without a caveat or unsourced.
0A core fact wrong or made up, a false premise accepted, the question missed, or the run failed or timed out.

Mapping to the Eval Desk

The desk scores 7 criteria from 1 to 5 (weights: useful 20, trading relevance 20, unique 15, evidence 15, calibration 10, answers the request 10, clarity 10) and turns them into 0–100. A critical flag caps the score at 40.

  • Every must-not violation becomes a critical flag, matching a 0 here.
  • Roughly: 2 ≈ Strong (75+), 1 ≈ 40–74, 0 ≈ capped or below 40.
  • Import files hold 50 questions each; the checklist goes in the desk's notes field for the judge.
  • Score only after every agent's answer is in, because "unique" is judged relative to the others.

Known gaps & next steps

Gaps

  • Checklists and tolerances are drafts and haven't been checked against real runs.
  • Template defaults go stale (specific price ranges, OTC claims, "latest" filings), so rotate them each run.
  • One wallet question still has a placeholder address.
  • Easy questions are thin (17 of 100).
  • Alert and watch questions measure capability; general agents can only explain that they can't set alerts.
  • The log sample is small: 172 exchanges and 17 threads.

Next steps

  • Build the script that saves reference data at send time.
  • Connect the runner to Raven, GPT and Claude, using the same 4-minute and tool budgets as the compare page.
  • Do a first full run, then calibrate the LLM judge against human grades.
  • Add regression items for known issues: "event 1/2" chart labels, the ~60 min taker-tape lag, repost time vs official time, follow-ups dropped mid-run, runs with 40+ tool calls.
  • Rerun weekly and on every change.
